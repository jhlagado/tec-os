# Bounded original CCP comparison

This diagnostic compares selected ordinary workflows against the reconstructed
Digital Research CCP. It is not a full parity gate and does not require adding
historical features. The accepted reference qualifier is unchanged.

The target is the descriptor-shared model generated by
`tools/ccp-call-model.mjs` at `07daed7d03565b8ec8cec8234d19365f67e87682`,
ROM SHA-256 `ab2d0c6b8a8d5d36ad3c51af3ef22cfb166890cc412f51bb9352b7a80cb27ed6`.
The tool refuses another ROM. Its result records the symbol-map hash, model-tool
hash and the exact host, filesystem and CCP/BDOS source hashes used. The target
model's own instructions explain its generation; this diagnostic consumes the
already built tree without modifying it.

From this branch with `npm ci` completed, run:

```sh
PORTABLE_CPM_REPO=/path/to/portable-cpm \
DEBUG80_REPO=/path/to/debug80 \
TECOS_MODEL_REPO=/path/to/tec-os-ccp-calls \
TECOS_COMPARE_ROOT=/path/to/tec-os-ccp-calls/build/ccp-calls-model/descriptor-shared \
node /path/to/origo/tools/mem-guard.mjs --limit 800 --heap 384 --wait 1800 \
  --name ccp-pair --log /tmp/ccp-pair-memory.jsonl \
  -- node tools/ccp-compare.mjs > /tmp/ccp-pair-result.json
```

Reference setup is the qualified pinned original-system adapter, including
source reproduction. The target uses its actual TEC-OS Machine with serial
input. Both systems receive identical explicit 128-byte file records; the
reference disk and TEC-OS G1M A: container keep their own physical geometries.
A: is written through. File comparison uses names, users, record counts and
complete record-content hashes after export and a fresh boot. It does not
compare allocation maps from unlike disks. Console output has no normalization.

## Observations and recommendations

The diagnostic at `ef542f7` completed on 4 November 2026 in 2.1 seconds at a
149 MB sampled guard peak. Raw observations and all pins are retained in
`test/fixtures/ccp-original-comparison.json`.

| Input or observation | Original system | TEC-OS | Recommendation |
| --- | --- | --- | --- |
| USER 0, USER 15 | Accept; expected user | Identical output and state | Keep |
| USER 16 | Reject; remain user 0 | Identical output and state | Keep |
| USER 00 | Accept zero | Reject with `00?`, remain zero | Optional permissive grammar; no demonstrated workflow need |
| USER 01 | Accept user 1 | Reject with `01?`, remain zero | Same optional compatibility choice; preserve incumbent during optimization |
| USER 1 EXTRA | Set user 1, then print `EXTRA?` | Print `1?` without changing user | Keep validation before side effects; do not copy historical partial execution |
| TYPE HELLO.TXT | Print explicit file payload | Identical raw output | Keep |
| REN OTHER.TXT=HELLO.TXT | Rename | Identical raw output and persisted logical file | Keep |
| SAVE 0 EMPTY.DAT | Create zero-record file | Identical raw output and persisted logical file | Keep |
| Reloaded disk | EMPTY.DAT 0 records, OTHER.TXT and PROBE.COM 1 record each | Identical names, users, records and complete content hashes | Keep; bounded evidence only |
| Transient `PROBE B:FOO*.BAR BAZ.QUX` | 19-byte tail, wildcard FCBs, DMA 0080h | Same tail, terminator, DMA and FCB contents except first RC | Keep |
| First default FCB record count, 006Bh | 1, retained from the loaded one-record COM | 0, cleared during parsing | Keep explicit initialization; do not emulate incidental loader state without a consumer need |
| Transient SP and return word | EBA9h, return EB5Fh into resident CCP | BE75h, return 0000h through warm boot | Intentional placement/lifecycle difference; both RET paths execute to prompt |

This is an observed difference inventory, not proof of a historical defect or
complete source attribution for all combined-system behaviour. The malformed
USER operand result agrees with each CCP's source ordering; neither leading-zero
acceptance nor historical batch support is required for this optimization.
No production change follows from this diagnostic by itself.

The initial diagnostic attempt stopped at setup because the model tool path
was misspelled. After correcting it, static preflight verified every pinned
blob, target path, imported export, required host symbol and ROM digest before
the successful guarded run. It produced no partial parity claim.
